# Git: Шпаргалка и Гайд по Основам

Этот документ — краткое руководство по настройке и основным командам Git. Здесь собраны команды для ежедневной работы, популярные флаги и советы по использованию.

1. Первоначальная настройка (Конфигурация)

Эти команды нужно выполнить один раз после установки Git на компьютер. Они сообщают Git, кто вносит изменения.

```bash
# Установить имя пользователя (будет видно в истории коммитов)
git config --global user.name "Твое Имя"

# Установить email (должен совпадать с аккаунтом GitHub/GitLab)
git config --global user.email "tvoj-email@example.com"

# (Опционально) Включить цветной вывод для удобства
git config --global color.ui auto

# Проверить текущие настройки
git config --list
```

> **Совет:** Используй `--global`, чтобы применить настройки для всех проектов на компьютере. Если нужно настроить имя только для одного проекта, убери этот флаг, находясь в папке проекта.

## 2. Создание и привязка репозитория

### Инициализация локального репозитория

Если у тебя есть папка с проектом, но там еще нет Git:

**Bash**

```
# Перейди в папку проекта
cd my-project

# Создать скрытую папку .git (инициализация)
git init
```

### Привязка удаленного репозитория (Remote)

Чтобы отправлять код на GitHub/GitLab.

**Bash**

```
# Связать локальную папку с пустым репозиторием на сервере
git remote add origin [https://github.com/username/repo-name.git](https://github.com/username/repo-name.git)
```

* `origin` — это стандартное имя для удаленного сервера (псевдоним).
* URL берется с кнопки "Code" или "Clone" на сайте GitHub/GitLab.

**Bash**

```
# Проверить, какой удаленный репозиторий привязан
git remote -v
```

## 3. Основные команды (Workflow)

Цикл работы обычно выглядит так: `Status` -> `Add` -> `Commit` -> `Push`.

### `git status` — Статус файлов

Показывает, что изменилось, что добавлено в индекс, а что нет.

* **Когда использовать:** Всегда перед `add` или `commit`, чтобы не добавить лишнего.

**Bash**

```
git status

# Флаги:
git status -s  # (short) Короткий формат вывода (меньше шума)
```

### `git add` — Добавление в индекс (Staging)

Подготовка файлов к коммиту.

**Bash**

```
# Добавить конкретный файл
git add filename.py

# Добавить ВСЕ измененные и новые файлы в текущей папке
git add .
```

### `git commit` — Фиксация изменений

Создает "снимок" состояния файлов с комментарием.

**Bash**

```
# Стандартный коммит с сообщением
git commit -m "Текст сообщения: что было сделано"

# Флаги:
git commit -am "Текст" 
# (all + message) Автоматически делает add для уже отслеживаемых файлов и сразу коммитит. 
# ВНИМАНИЕ: Не добавляет НОВЫЕ (untracked) файлы.
```

> **Совет:** Пиши понятные сообщения. Не "fix", а "Исправлена ошибка валидации данных".

### `git log` — История изменений

Показывает список коммитов.

**Bash**

```
git log

# Флаги:
git log --oneline        # Каждый коммит в одну строку (хеш + название)
git log --graph          # Рисует "дерево" веток (полезно при слияниях)
git log -n 5             # Показать только последние 5 коммитов
git log --oneline --graph --all # Красивое дерево всей истории
```

## 4. Синхронизация с сервером

### `git push` — Отправка изменений

Загружает твои локальные коммиты на удаленный сервер.

**Bash**

```
# Отправить текущую ветку на сервер
git push origin main 
# (или master, в зависимости от названия главной ветки)

# Флаги:
git push -u origin main  
# (set-upstream) Использовать при ПЕРВОЙ отправке ветки. 
# В будущем можно будет писать просто `git push`.

git push --force (или -f)
# Переписать историю на сервере. ОПАСНО! 
# Используй только если ты один работаешь в ветке.
```

### `git pull` — Получение изменений

Скачивает изменения с сервера и сливает их с твоими.

**Bash**

```
git pull

# Флаги:
git pull --rebase
# (Рекомендуется) Сначала скачивает изменения, а потом накладывает твои коммиты ПОВЕРХ них. 
# Позволяет избежать лишних merge-коммитов и делает историю чище.
```

## 5. Полезная шпаргалка по ситуациям


| **Ситуация**                                                                                                        | **Команда**                                                                     |
| --------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| **Случайно изменил файл, хочу вернуть как было**                                       | `git restore filename`(или`git checkout -- filename`в старых версиях) |
| **Хочу убрать файл из индекса (отменить git add)**                                           | `git restore --staged filename`                                                        |
| **Изменил последний коммит (забыл добавить файл/поменять название)** | `git commit --amend`(не делай этого, если уже запушил!)      |
| **Создать новую ветку и перейти в нее**                                                        | `git checkout -b new-feature-name`                                                     |
| **Удалить ветку (после слияния)**                                                                   | `git branch -d branch-name`                                                            |
